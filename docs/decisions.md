# Design decisions

A short record of each important choice and why it was made. Recruiters often ask "why did you do
it this way?": this file is the answer.

| # | Date | Decision | Why | Alternatives considered |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-13 | `src/` layout with one subpackage per stage | Tests import the installed package, not loose files; each stage can be tested alone | Flat scripts, notebooks |
| 2 | 2026-10-13 | uv for environments and dependencies | One fast tool, a lock file for reproducible installs | pip + venv, Poetry |
| 3 | 2026-10-13 | Settings from environment variables via pydantic-settings | Secrets never in code; same code runs locally, in CI and in production | Hard-coded constants, config files |
| 4 | 2026-10-13 | Raw, interim and processed data kept out of Git | Large files and third-party texts don't belong in the repo; the pipeline rebuilds them | Committing data, Git LFS |
| 5 | 2026-10-13 | ruff + pre-commit + CI from day one | Consistent style, bugs caught before review, a green badge recruiters can see | Manual checks |
| 6 | 2026-10-13 | Parse PDFs using font size and weight, not plain text | In the Adala PDFs, chapters (16 bold), articles (15 bold), body (14) and footnotes (12) each have their own font. Plain text loses that, and footnotes quote other laws' articles ("Article 34:") that a text-only regex would take for real articles | Regex on plain text, an LLM to split articles |
| 7 | 2026-10-13 | Per-source `LayoutProfile` instead of hard-coded sizes | Each family of PDFs has its own fonts; a new family means a new profile, not a new parser | One parser per document |
| 8 | 2026-10-13 | Drop small superscript digits, keep small superscript letters | Digits are footnote markers ("traitement³"); letters are ordinals that change the meaning ("2e alinéa", "1er") | Drop all small text (lost "2e"), keep all (polluted words) |
| 9 | 2026-10-13 | Never correct the law's wording, even obvious typos | We cite the law: our text must match the source. Typos are recorded in docs/corpus.md instead | Spell-correcting during cleaning |
| 10 | 2026-10-13 | Quality checks that fail the build (numbering gaps, duplicates, short articles, footnote leaks) | A parser that silently loses an article is worse than one that crashes | Manual spot checks only |
| 11 | 2026-10-13 | Repair Arabic ligatures using glyph width, not text patterns | Ligature letters come out reversed; the zero width of all but the last letter identifies them exactly. Text patterns can't tell a broken "أل" from a real one ("الإلكتروني") | Find-and-replace on letter pairs, OCR |
| 12 | 2026-10-13 | Rebuild Arabic reading order from character positions | The extractor misplaces spaces, punctuation and quotes in right-to-left text, but their positions are reliable | Full Unicode bidi algorithm on the extracted text, other PDF libraries |
| 13 | 2026-10-13 | One parser for both languages: fonts in `LayoutProfile`, heading words in `LanguageRules` | French and Arabic laws share the same structure; only fonts and words differ | Separate French and Arabic parsers |
| 14 | 2026-10-13 | Same article ids across languages (`loi-09-08-fr-art-N` / `-ar-art-N`) | Lets the assistant show the official Arabic text next to the French one, and match a question in one language to the article in the other | A separate translation table |
| 15 | 2026-10-13 | Rebuild each line from all its characters, ignoring how the PDF cuts it into spans | The Labour Code splits words and shadowed headings into pieces that, ordered piece by piece, interleave. Ordering the whole line by position is independent of the cut | Fixing span boundaries case by case |
| 16 | 2026-10-13 | Drop shadow copies by comparing character, font, width and position (≤ 1.5 pt) | Headings are drawn twice for a shadow effect. Comparing widths keeps the hidden zero-width alef of a ligature, which a position-only rule deleted ("الاتفاقيات" → "التفاقيات") | Removing duplicate lines, image-based OCR |
| 17 | 2026-10-13 | Rescue article headings printed in the footnote font, and report each rescue | "المادة 517" is mis-formatted in the official PDF; without the rescue, article 517 silently merges into 516. The quality check caught it through the numbering gap | Hard-coding a fix for article 517 |
| 18 | 2026-10-13 | Heading levels as an ordered list per layout (book → sub-section) | Codes have up to 5 levels, small laws 2; one parser handles any depth | A fixed chapter/section model |
| 19 | 2026-10-13 | Use the consolidated Arabic Labour Code (16 July 2026) as the main source | It is official and current; the French version on Adala dates from 2011 and misses 15 years of amendments | Using the outdated French text |
| 20 | 2026-10-13 | Any change to the PDF reader is checked by rebuilding earlier laws and comparing them word for word | A repair for one document must not silently change another | Relying on tests only |
| 21 | 2026-10-13 | A heading's level is decided by its font **and** its first word together | In the Family Code, chapters and sections share one font; size alone put sections at the wrong level | Size only, position on the page |
| 22 | 2026-10-13 | A short article is suspicious only if it is tiny (< 15 chars) or doesn't end like a sentence | 14 real one-line articles were flagged ("سن الرشد القانوني 18 سنة شمسية كاملة."); truncated articles end without final punctuation | A fixed length threshold |
| 23 | 2026-10-13 | pre-commit runs ruff through `uv run`, not a separately pinned copy | The hook pinned ruff 0.6.9 while CI used 0.17.0 from uv.lock; they format differently, so pre-commit produced code CI rejected (PR #7) | Pinning the same version in two places |
| 24 | 2026-10-13 | Measure retrieval with a fixed test set of 45 questions before building the search | A search change is only an improvement if a number says so. The set mixes Arabic, French, Darija in Arabic script and Arabizi, formal and everyday wording; every expected article was checked against the corpus | Judging results by eye |
| 25 | 2026-10-13 | BM25 written by hand as the baseline, with Arabic normalisation (vowel marks, alef forms, ة/ى, glued prefixes) | Explainable line by line, no dependency; it sets the score the embedding search must beat (47% hit@5) | rank-bm25 or Qdrant's built-in BM25 |
| 26 | 2026-10-13 | Embeddings computed on the user's PC (8 GB RAM), not in the build workspace | The workspace can't download models (Hugging Face blocked) and has no GPU; the model must run locally anyway to embed each new question. A free cloud notebook is the fallback for the one-time batch | A paid embedding API |
| 27 | 2026-10-13 | Real-PDF tests tagged `slow` and skipped by default | Everyday test runs drop from about 80 s to under 1 s; `pytest -m slow` runs them when the parser changes | Running everything every time |
| 28 | 2026-10-13 | BGE-M3 as the embedding model, through sentence-transformers | One multilingual model for Arabic and French questions and articles, no query/passage prefixes, up to 8,192 tokens, open weights that run on a laptop. fastembed (lighter, no torch) doesn't offer it | multilingual-e5-large, paid embedding APIs |
| 29 | 2026-10-13 | Embed whole articles (headings + text), cut at 1,024 tokens | Citations are per article, so one vector per article keeps "retrieved" and "cited" the same thing. Median article is ~400 characters; only 2 of 1,329 exceed the limit | Fixed-size chunks, 512 tokens |
| 30 | 2026-10-13 | Cache vectors on disk with a fingerprint of the model and every text | Embedding takes minutes on a CPU; re-loading Qdrant from the cache takes seconds. Any change to the text or model invalidates the cache automatically, so it is never stale | Re-embedding every time, manual cache deletion |
| 31 | 2026-10-13 | Hybrid = our BM25 + Qdrant dense search, fused with Reciprocal Rank Fusion (k = 60) | RRF uses ranks only, so BM25 and cosine scores need no calibration. Keeping our BM25 keeps its Arabic normalisation, which Qdrant's built-in sparse vectors lack | Weighted score sum, Qdrant sparse vectors, BGE-M3 sparse output |
| 32 | 2026-10-13 | Embedding libraries (torch) in an optional dependency group, installed by default locally and skipped in CI | CI stays fast and small (torch on Linux pulls several GB); tests use a hashing embedder and Qdrant's in-memory mode | Mocking everything, installing torch in CI |
| 33 | 2026-10-13 | Qdrant can also run as a folder inside the Python process (`QANOUN_QDRANT_URL=data/qdrant`) | The development PC (8 GB, under 1 GB free) can't hold the model next to everything else, so the first embedding run happens in a Kaggle notebook, which has no Docker. Same code, same results; the Docker server stays the default | A separate script for notebooks, numpy-only search |
| 34 | 2026-10-14 | Dense search is the default; hybrid is kept only for measurement until it is weighted | Measured on 45 questions: dense 82% hit@5 vs hybrid 73% vs BM25 47%. BM25 fails across languages (French or Darija question, Arabic article), and equal-weight RRF lets those misses outvote the dense ranking. Numbers beat intuition: "hybrid is always better" was false here | Shipping hybrid because it is the usual best practice |
| 35 | 2026-10-14 | Understand the question before searching: detect the language, convert Arabizi to Arabic script, add legal terms from a Darija lexicon | Dense search reached 100% on Arabic and French but 22% on Arabizi: digits as letters ("l7e9") and everyday words ("tredouni", "lkhedma") are far from the law's vocabulary. The original question is always kept, so a wrong conversion can't lose information | Translating every question with an LLM (cost, latency, and nothing to measure offline) |
| 36 | 2026-10-14 | Language detection and Arabizi conversion by rules, not a model | Instant, explainable, and testable: 45/45 labelled questions detected correctly. Very common words ("chhal" → شحال) use a fixed spelling instead of the letter rules | A language-ID model (fastText), a neural transliterator |
| 37 | 2026-10-14 | An open Darija → legal-Arabic lexicon as a CSV (54 entries, four laws) with regular expressions for Arabizi spellings | Readable and editable by a non-programmer, versioned in Git, reusable by others. Regular expressions absorb spelling variation (khedma / lkhdma / flkhedma) | A hard-coded dictionary, embeddings only |
| 38 | 2026-10-14 | Measure each part separately (ablation) and keep a held-out set of questions written by a native speaker who never saw the lexicon | The lexicon was written while looking at the 45 development questions, so their scores are optimistic. Only the held-out set shows whether it generalises | Reporting the development score only |
| 39 | 2026-10-14 | The held-out set is scored before any fix; failures it reveals are logged, not patched in place | Held-out BM25 + lexicon: 50% (development: 56%), so the lexicon generalises. Its misses ("trde3", "sway3 zaydin", "yjri", "nrfed" spelled differently from the patterns; "rj3at lkhdma" taken for "return a product") go into the next lexicon version, which will then need a fresh held-out set | Fixing the lexicon on the held-out questions, which would make the held-out score meaningless |
| 40 | 2026-10-14 | Default question pipeline = language detection + lexicon; Arabizi → Arabic script off by default | Real-model ablation (Kaggle, BGE-M3): lexicon alone 96% overall, Arabizi 78% (dev) / 50% (held-out); adding the script conversion drops Arabizi to 33% / 42%; the conversion alone 11% / 0%. Unmodified BGE-M3 finds 0 of the 12 native-speaker Arabizi questions | Keeping a component because it seemed useful in theory |
| 41 | 2026-10-14 | Google Gemini as the first LLM, called through its REST API with httpx behind a small `LLM` interface | Free tier, good Arabic and French; REST keeps every request visible and adds no SDK; the interface makes the provider swappable. The key travels in a header, never in a URL (URLs end up in logs) | Google's SDK, a paid provider, a local model (not possible on an 8 GB PC) |
| 42 | 2026-10-14 | Pick the model from what the key can use (newest stable "flash"), overridable in `.env` | Google renames models often; a hard-coded name breaks silently | Hard-coding a model name |
| 43 | 2026-10-14 | Sources are numbered [1]…[k] and the model answers in JSON (status, answer, used sources) | A number is checkable: it is one of the sources we gave or it is wrong. JSON separates "answered" from "not covered" without parsing prose | Free-text answers citing "article 13 of law 65.99" |
| 44 | 2026-10-14 | Every answer is checked: unknown markers removed, at least one citation required, every article number written must belong to (or be quoted in) a cited source; one retry with the problems spelled out; still wrong → shown with a warning | A legal assistant that invents an article is worse than one that says it doesn't know. Flagging instead of hiding keeps the system honest and measurable | Trusting the model, asking it to "be careful" |
| 45 | 2026-10-14 | Answer in the language and script of the question (Arabizi in, Arabizi out) | People read best what they wrote; the legal term can be quoted in Arabic in parentheses | Always answering in Arabic or French |
| 46 | 2026-10-14 | When Gemini is busy (429/5xx): try each stable model once, newest flash first and "lite" last; only when all are busy, wait (2 s, 4 s) and go round again; other errors stop at once. Every attempt is logged with its time | The free tier returned "503: high demand" on the first real call. The first version waited on each busy model before moving on: one answer took 117 s. A bad key is not worth retrying | Failing on the first error, retrying one model with waits |
| 47 | 2026-10-14 | Give up on a model after 25 s; during a session try busy models last; remember between runs the model that answered and the ones refused (git-ignored `data/cache/llm.json`) | Logs of one answer (258 s): two overloaded models hung 60 s each before "503", and the citation retry started again with the same two. The models that worked answered in 1–6 s | A fixed model in `.env` (breaks when that model is busy), no timeout |
| 48 | 2026-10-14 | Evaluate full answers, not only retrieval: answered, correct citation (cites an expected article), verified, refused with the answer in hand, time | Retrieval at 96% says the right article is *available*; only the answer shows whether the model used it, cited it, and didn't refuse wrongly. Each run keeps every answer (Markdown + JSONL) for error analysis; one failing question doesn't stop the run | Reading a few answers by eye |
| 49 | 2026-10-14 | The retry shows the model its previous answer and the problems; a refusal on retry never replaces a first answer (that one is shown, marked unverified); every attempt is logged and kept in reports | On Kaggle the first answer to "chhal dyal lconji" was rejected and the retry refused, although article 231 was among the sources. Also: the Arabizi style example in the prompt was the answer to that very question; replaced by a neutral one | Retrying blind, trusting the last attempt |
| 50 | 2026-10-14 | Give the model 6 search results plus up to 3 opening articles of the section most results share ("section expansion"); report "retrieved" (an expected article was among the sources) in the answer evaluation | "chhal dyal lconji 3ndi f l3am?" retrieved articles 234–242 of the paid-leave section but not 231, which states the rule (long articles score lower). With keyword search on the 45 questions: 5 results 25/45, 8 results 28/45, 5 + 3 from the section 30/45 at the same size. "Retrieved" tells a search failure from a model failure | More results only, a re-ranker (later) |
| 51 | 2026-10-14 | Next target: the search on real Arabizi, not the model | Answer evaluation: on 45 questions 98% cite the right article, 100% pass the citation check, 0% wrong refusals, median 1.4 s; on the 12 held-out Arabizi questions every failure is a retrieval failure (50% retrieved = 50% correct). Improving the prompt would change nothing measurable | Tuning the prompt further |
| 52 | 2026-10-14 | For Darija questions only, the LLM restates the question in formal legal Arabic and that line is added to the search query (question + lexicon terms + restatement); measured as `+rewrite` and `+llm` variants | The lexicon only knows the spellings it lists; real Arabizi has endless ones. The prompt was written before any held-out result and uses general legal vocabulary. The restatement never replaces the question and a busy model just skips it, so it can't make the search worse than the lexicon alone by failing | Translating every question (cost and delay for French and Arabic, already at 100%), replacing the question by the rewrite |
| 53 | 2026-10-14 | The LLM restatement is used for Arabizi only, and is on by default | Kaggle, dense search, hit@5. Held-out Arabizi (12): lexicon 50% → lexicon + rewrite 92% (MRR 0.32 → 0.79), rewrite alone 92%. Development: Arabizi 78% → 89%; Darija in Arabic letters 100% → 75% (1 of 4 questions; small sample), Arabic and French unchanged at 100%. Keeping the lexicon too: equal on held-out, better on development | Rewriting all Darija, the rewrite alone |
| 54 | 2026-10-14 | Freeze this pipeline as the Phase 3 baseline; any change must be re-measured on both question sets | Full-assistant results: development 100% correct citations; held-out Arabizi 92% (was 50%), 100% citation check passed, 0% wrong refusals, median 4.7 s (rewrite call included). The held-out set has now guided one design choice (decision 53): a fresh held-out set is needed before claiming further gains | Continuing to tune on the same held-out questions |
| 55 | 2026-10-14 | Run the app on the 8 GB PC with the 8-bit ONNX BGE-M3 (Xenova/bge-m3, 568 MB, onnxruntime, no torch) for questions, and the full-precision article vectors already computed | Kaggle, hit@5 (dense + lexicon): full model 96% / held-out 50% (MRR 0.32); 8-bit questions + full articles 93% / 50% (MRR 0.36); 8-bit everything 93% / 50% (MRR 0.36). Arabic, French and Arabizi identical; the only loss is 1 of 4 Darija questions in Arabic script. 4× smaller, no torch. The index now reuses cached vectors without loading the model | Switching the PC to Linux (frees ~2 GB, still tight, and doesn't help deployment), a hosted embedding API, the full model on a paid server |
| 56 | 2026-10-14 | FastAPI service; the stream sends progress steps (understood → sources → writing) then the checked answer, never unchecked text word by word | Every citation is verified before anything is shown, so token streaming would display text that may be withdrawn. Steps give feedback within a second. The assistant is built on the first question and once only (a lock), so the service starts instantly | Streaming raw tokens and correcting afterwards, WebSockets |
| 57 | 2026-10-14 | Web interface in plain HTML, CSS and JavaScript served by the API (no build step); design from a brief the owner chose through multiple-choice questions (docs/design.md) | Runs wherever the API runs, including the 8 GB PC, with nothing to install; easy to read in an interview. Navy and gold on ivory, Moroccan zellige star as the one memorable element, RTL/LTR per interface language and per answer, reduced motion respected | React / Next.js (Node toolchain, build step) |
| 58 | 2026-10-14 | A number glued to a French unit ("2ans", "3mois", "48h", "2e", "300dh") is not Arabizi; the French answer instruction says to translate the Arabic sources | Reported by the owner: a French question got a Darija answer. "2ans" matched the digit-inside-a-word rule meant for "3ndi" or "l7e9". 19 French questions are now a regression test, and both Arabizi test sets are still fully recognised | A language-ID model |
| 59 | 2026-10-14 | Grow the corpus from Adala's own catalogue: read each page's Next.js JSON (`__NEXT_DATA__`) for all 63 subjects (~5,500 documents, ~400 requests), keep laws (dahirs) first, download politely (1 request/s, identifying User-Agent, page cache, resume) | The owner wants all laws. Adala is the official source; its pages carry structured data (type, number, subject, date, PDF path), so no fragile HTML scraping. Most documents are circulars, treaties and decrees: filtering by type keeps the corpus relevant. Downloaded once, PDFs can be deleted after parsing; answers link to the official PDF | Fetching laws live at question time (slow, no semantic search), scraping HTML, a third-party dataset (none covers Moroccan law broadly) |
| 60 | 2026-10-14 | Parse every Adala law with one generic parser that measures each PDF's layout (body font, article font, heading levels, line spacing) instead of a hand-made profile per law; the five curated laws keep their profiles | 960 laws in many layouts: hand profiles don't scale. Measured on a sample of 87 laws (including the DOC, Penal Code, Criminal and Civil Procedure, Commerce): article counts plausible, DOC art. 230 and Penal art. 400 exact, ligatures clean. The curated dataset is rebuilt byte-identical | Writing a profile per family of PDFs, an LLM to cut the articles, the plain text without structure |
| 61 | 2026-10-14 | Read PDFs without decoding their images (`rawdict` without `TEXT_PRESERVE_IMAGES`) | Every Adala page carries a logo: decoding it made text extraction 50× slower for the same characters (sample of 87 laws: 8 min → 73 s; all 960 in about 6 min) | Parallel processes, another PDF library |
| 62 | 2026-10-14 | Which laws enter the corpus: Adala's law types, plus laws it files as "decrees" whose title is a dahir (the Highway Code 52.05 is listed as مرسوم); minus annual finance laws, laws marked "(نسخ)", the 1962–1992 constitutions, the five curated laws, and older PDFs of the same law. Repealed articles ("(نسخ).") and the closing signature are dropped | Out-of-date or budget texts would produce wrong or useless answers; one PDF per law avoids duplicate sources. Result: 818 laws → 798 parsed (16 without article headings, 4 scanned), **33,184 articles**; with the curated laws **34,513** | Taking every document of the catalogue (decrees, circulars, treaties: 4,500 more texts, mostly technical) |
| 63 | 2026-10-14 | Cite an article with the word its law uses (الفصل in the DOC, the Penal Code and old dahirs, المادة elsewhere), stored per article; Adala's Arabic texts are marked as the official-language text, not a translation | "المادة 400 من مجموعة القانون الجنائي" would be a wrong citation; the panel showed "translation" for Arabic texts | Always "المادة" |
| 64 | 2026-10-14 | Switch the assistant to the full corpus (`QANOUN_CORPUS=full`, own Qdrant collection and vectors file); the core corpus stays selectable for comparisons | Kaggle, same questions, 26× more articles. Answers (full pipeline): development 96% correct citations (was 100%: one Darija question in Arabic script), 100% verified, 0 wrong refusals, 2.5 s median; held-out Arabizi 92% (unchanged). Search alone, dense + lexicon: 84% hit@5 (was 96%): misses are mostly neighbouring articles of the right law, recovered by section expansion, or similar articles of another law (the domestic-workers law for the minimum working age). BM25: 47% → 42% | Staying on 5 laws; boosting "important" laws by hand before measuring a need |
| 65 | 2026-10-14 | Leave out international treaties published or approved by a dahir (20 texts, 407 articles); a smaller corpus reuses the saved vectors (one fingerprint per article in the vectors file) | First test on the PC: a rent question found the UN convention on migrant workers and an African Union convention, and the answer was "not covered". Treaties bind states; citizens' questions are about Moroccan laws. Domestic charters (Communal Charter, investment charter, arbitration) stay. Corpus: 778 laws, 32,777 articles (34,106 with the curated laws). Removing articles must not cost another 25-minute embedding run | Down-weighting treaties at search time; re-embedding on Kaggle |
| 66 | 2026-10-17 | On the PC, search the saved article vectors in memory with numpy (`QANOUN_VECTOR_STORE=numpy`) instead of Qdrant's folder mode; Qdrant stays for the server and for Kaggle | Loading 34,106 articles into Qdrant's folder mode on the 8 GB PC never finished (Qdrant warns past 20,000 points: it rewrites its files on each insert). A brute-force search over 34,106 × 1,024 numbers takes ~4 ms, ranks exactly like Qdrant (test), and needs no index step: the vectors file from Kaggle is read at start-up | Qdrant in Docker (another 1–2 GB of RAM on the PC), an approximate index (FAISS, hnswlib) for a corpus this small |
| 67 | 2026-10-17 | Long articles (over 1,500 characters) also get passage vectors: **one per list item** (after the opening sentence and the sentence that opens the list) and ~900-character windows for other paragraphs, each repeating the article's opening sentence; an article scores as its best vector (article or passage), and the answer still gets the whole article | Owner's test: "chhal dyal lghrama ila sou9t b tilifoun f yddi?" → "not covered", although Highway Code art. 185 says it (a 4,640-character list of 15 offences, one fine). The right law was found, not the article: one vector averaged all 15 offences. 2,872 passages, embedded once with the PC's 8-bit model (`python -m qanoun.retrieval.passages`), only new ones on later runs | Cutting every article into chunks (the short ones are already precise), a bigger model with longer context |
| 68 | 2026-10-17 | Lexicon v2: 11 entries for the new laws (rent: الكرا, مول الدار, الكاري, يزيد, يخرجني; road: تيليفون, sou9, permis, الخطية; penal: سرقة/شفر, الحبس); the owner's test questions go into `eval/owner_tests.jsonl` (a development set, not held-out) | Owner's test: rent-increase question → "not covered" although Law 67.12 arts. 32–34 answer it (every 3 years, 8% for housing): Darija words (الكاري, يزيد فالكرا) never meet the law's (المكتري, الوجيبة الكرائية, الرفع). BM25 on the 4 owner questions: 0% → 50% hit@5; the 45-question set unchanged (56%) | Relying on the LLM rewrite alone (Arabizi only, decision 53) |
| 69 | 2026-10-18 | Passages per list item rather than 900-character windows (7,714 passages instead of 2,794) | PC, owner tests, dense + lexicon: 3 of 4 found after the windows, but art. 185 still missed: its window held 3 other offences besides the phone. A list item is one rule; its penalty is in the opening sentence, which each passage repeats. Cost: about 35 min of embedding once on the PC, only changed passages later | Smaller windows (cut mid-sentence), more weight on the lexicon terms |
| 70 | 2026-10-18 | Lexicon v3 (+13 entries): repairs and paying rent, hitting and self-defence, messages and surveillance at work, cheques without funds and prescription, building without a permit and neighbours, seniority, an absent husband and unpaid alimony | Owner tests H3, H5, H8, H9, H11, H1, H2, H4: everyday words never met the law's ("يصلح/كيقطر" vs "الإصلاحات", "darbt… howa bda" vs "الدفاع الشرعي", "bla rassid" vs "مؤونة الشيك"). "khlas" (salary) deliberately left out of the rent-payment entry. 45-question set unchanged (BM25 56%) | Waiting for the agent (step 2 of the roadmap) |
| 71 | 2026-10-18 | Articles the question names ("l'article 400 du Code pénal", "المادة 10 من القانون رقم 67.12") are looked up directly and put first among the sources; a named article that does not exist is reported to the model with the law's last article number; the answer may repeat article numbers taken from the question | Owner tests H10 and Q13: questions built on a wrong premise got "not covered", because search finds articles by meaning, not by number. Twelve usual law names (Code pénal, Moudawana, DOC…) plus "loi 67.12"-style numbers; only when exactly one law is named | Letting the model answer from memory |
| 72 | 2026-10-18 | A third answer status, "clarify": a question too vague or too broad ("حقوقي", "every article of every law") gets one short question back with two or three precise topics; new prompt rules: correct a wrong premise first, answer each side of a two-sided question, mention the text's date when the question is about what is in force | Owner tests H12 (no answer) and H5 (civil vs criminal sides of a cheque) | Refusing ("not covered") |
| 73 | 2026-10-18 | Every article shows how recent its text is: the consolidation date the PDF states («صيغة محينة بتاريخ…», about a quarter of Adala PDFs, read at the next parse) or else the day Adala published that version (from the PDF address); given to the model and shown in the article panel | Owner test H7 ("is the new Family Code in force?"): "not covered" was right, but the answer should say which version it relies on | Showing nothing; guessing from the law's original date |
| 74 | 2026-10-18 | Home page: 15 themes for the whole corpus (work, family, rent, criminal law, road first; then consumer, data, property, contracts, business, courts, civil status, work accidents, urban planning, women and children), 5 shown, the rest behind "all themes"; the corpus line counts laws from `/health` | The owner's request; the page still said "4 texts" after the corpus grew to 783 laws | All 63 Adala subjects (administrative, not citizen-oriented) |
| 75 | 2026-10-18 | "Analyse my situation" mode: the model first plans the research (the facts that matter, 2–4 searches in the law's own Arabic words, the missing facts), each search is run (4 articles each, at most 14 sources), then it writes five sections — situation · what the law says · what it means for you · what you can do · what is missing — checked like any answer (one retry); a broken plan falls back to a quick answer | Owner's request: analyse a problem, not only find an article.
